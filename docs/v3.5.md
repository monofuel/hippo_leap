# v3.5 — Sampling, batching, and production features

Make the inference server behave like a real production endpoint with proper
sampling, request batching, and operational features.

## Tasks

### Temperature and top-p sampling
- Implement softmax over logits with temperature scaling
- Top-p (nucleus) sampling: sort by probability, cumulative cutoff
- Top-k sampling: keep only top K logits
- Seed support for reproducible generation
- `temperature=0` maps to current greedy argmax behavior

### Stop sequences
- Support `stop` field in chat completions request
- Check each generated token's text against stop sequences
- Set `finish_reason` to `stop` vs `length` correctly

### Request batching
- Queue incoming requests and batch them for prefill
- Multiple sequences share the GEMM prefill kernel (already handles batch dim)
- Each sequence gets its own KV cache slot
- Significant GPU utilization improvement under concurrent load

### Continuous batching
- Don't wait for all sequences in a batch to finish
- As sequences complete (hit EOS or max_tokens), replace them with new requests
- Keeps the GPU busy even with variable-length outputs

### Operational features
- Request logging with timing (prompt tokens, completion tokens, tok/s)
- CORS headers for browser-based clients
- API key validation (optional, via env var)
- Graceful shutdown (finish in-flight requests, then stop)
- `/v1/models/:id` endpoint for model details

### Proper finish_reason
- `stop` — hit EOS token or stop sequence
- `length` — hit max_tokens limit
- `content_filter` — future, if we add safety filtering

## Success criteria

- `temperature=0.7` produces varied outputs across requests
- Concurrent requests batch efficiently (>1 sequence per GEMM)
- Server logs per-request metrics
