# v2 — Broader model support

Run real-world models beyond TinyLlama. The immediate target is Llama 3.2 3B,
which validates the architecture generalizes and gives us a usable model for
real inference workloads.

## Tasks

### Add Q4_K and Q5_K quantization support
- Port `dequantRowQ4K` and `dequantRowQ5K` to `quant.nim` (CPU dequant)
- Add GPU GEMV kernels for Q4_K and Q5_K in the naive backend
- Add row size calculations and block size constants
- Unit tests for known dequant values

### Llama 3 architecture compatibility
- Verify GGUF metadata key names match (Llama 3 uses the same `llama.*` keys)
- Handle different GQA ratios (Llama 3.2 3B: nHead=24, nHeadKv=8 vs TinyLlama nHead=32, nHeadKv=4)
- Verify RoPE frequency base differences (Llama 3 uses 500000.0 vs TinyLlama 10000.0)
- Test with different vocab sizes (Llama 3: 128256 vs TinyLlama: 32000)

### Tokenizer updates
- Llama 3 uses BPE tokenizer (not SentencePiece) — verify our tokenizer handles both
- Llama 3 chat template uses `<|begin_of_text|>`, `<|start_header_id|>`, etc.
- May need to update `formatChatPrompt` for the new template format

### Integration test with Llama 3.2 3B
- Add golden output test with a Q4_K_M model
- Benchmark decode tok/s and compare with llama.cpp

## Models to test

- `Llama-3.2-1B-Instruct-GGUF` (Q4_K_M) — smallest, fastest iteration
- `Llama-3.2-3B-Instruct-GGUF` (Q4_K_M) — primary target
- Keep TinyLlama Q2_K as regression reference

## Success criteria

- Llama 3.2 3B Q4_K_M produces coherent output
- All existing TinyLlama tests still pass (no regressions)
- Decode performance within 80% of llama.cpp for equivalent model/quant
