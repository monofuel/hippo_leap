# v4 — FlashAttention and performance

Close the performance gap with llama.cpp and push beyond it. The naive backend
is a faithful port — this version optimizes the hot path.

## Tasks

### FlashAttention-style tiled attention
- Replace flat shared-memory attention with tiled KV cache reads
- Online softmax with inter-tile correction (no full score materialization)
- Separate code paths for prefill (batched queries) and decode (single query)
- Target: handle 2K+ context without attention becoming the bottleneck
- See `docs/future.md` "FlashAttention-style tiled attention" for prior analysis

### hipGraph kernel batching
- Record the decode kernel sequence into a hipGraph
- Replay with minimal CPU overhead (only pos changes per step)
- Expected 50-80% reduction in kernel launch overhead
- Lower risk than persistent kernels, good bang-for-buck

### Fused kernels
- Fuse RMSNorm + Q projection (eliminate intermediate global memory write)
- Fuse down projection + residual add (fold into GEMV epilogue)
- Fuse residual + RMSNorm already exists — extend the pattern

### Profiling infrastructure
- Add `-d:profileHippo` build that emits per-kernel timing
- Track bandwidth utilization vs theoretical peak
- Automated benchmark suite (tok/s at various context lengths)
- Compare against llama.cpp on same hardware/model

## Performance targets

Reference: tinylama = 371 tok/s on 7900 XTX, TinyLlama 1.1B Q2_K

- Short context (<128 tokens): match or beat tinylama baseline
- Medium context (512 tokens): within 90% of short-context speed
- Long context (2048 tokens): no more than 30% regression from short-context
