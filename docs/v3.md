# v3 — Streaming and server hardening

Make the server production-usable: streaming responses, better error handling,
and the GPU/API build split.

## Tasks

### SSE streaming responses
- Implement Server-Sent Events for `/v1/chat/completions` when `stream: true`
- Mummy doesn't natively support streaming — investigate options:
  - Raw socket write with chunked transfer encoding
  - Upgrade to websocket-based streaming
  - Or use mummy's response callback if available
- Each decoded token sends a `data: {...}` chunk with a delta message
- Final chunk includes `finish_reason: "stop"` and usage stats

### Split GPU/API into separate build units
- Compile GPU inference as `libhippo_leap_gpu.so` with `nim cpp --cc:hipcc --app:lib`
- Compile HTTP server with regular `nim cpp` (full SIMD, no `-d:zippyNoSimd`)
- Use treeform/genny for the FFI boundary between the two
- See `docs/split-gpu-build.md` for detailed design
- Benefits: faster builds, full zippy SIMD, potential runtime backend swap

### Error handling and robustness
- Graceful handling of GPU OOM (catch hippo allocation failures)
- Request timeout for inference (kill long-running generations)
- Better error messages in JSON error responses
- Log inference timing per request (prompt tokens, completion tokens, tok/s)

### Configuration improvements
- Model name override via env var (instead of showing arch + vocab)
- Configurable default max_tokens from the request
- Health endpoint reports model loaded status and GPU info

## Success criteria

- `stream: true` works with standard OpenAI client libraries
- Server handles concurrent requests gracefully (queue or reject)
- Build no longer requires `-d:zippyNoSimd`
