# v2.1 — Multi-architecture support

Run fine-tuned Qwen and NeMo models on hippo_leap. These are the models we're
actually training and using — making them work on our own stack is the
immediate goal.

## Target models

Dense (Llama-like, should be straightforward):
- Qwen 3.5 4B (fine-tuned)
- NeMo 4B (fine-tuned)

MoE (needs new kernel work):
- Qwen 3.6 35B A3B (fine-tuned, ~3B active params)
- NeMo 30B A3B (fine-tuned, ~3B active params)

## Tasks

### Generalize architecture detection
- Read `general.architecture` from GGUF and dispatch on it
- Remove the hard `arch != "llama"` error
- Read model config from architecture-prefixed GGUF keys
  (e.g., `qwen2.embedding_length` instead of `llama.embedding_length`)
- Map architecture names to a common HParams struct

### Qwen dense support
- Investigate GGUF key differences for Qwen models
- Handle any attention variations (Qwen uses standard GQA)
- Handle any FFN variations (Qwen uses SwiGLU like Llama)
- Verify RoPE config (Qwen may use different base or scaling)
- Tokenizer: Qwen uses BPE — verify compatibility with existing BPE tokenizer
- Chat template: Qwen has its own format — add template support
- Integration test with Qwen 3.5 4B fine-tune

### NeMo dense support
- Investigate GGUF key differences for Mistral/NeMo models
- Handle any architecture differences vs Llama
- Tokenizer and chat template support
- Integration test with NeMo 4B fine-tune

### MoE support (Qwen A3B, NeMo A3B)
- Expert routing: top-k gating layer that selects active experts per token
- Multiple FFN weight sets per layer (one per expert)
- Sparse dispatch: only run selected experts, not all
- Possibly shared experts (some MoE architectures have these)
- GPU kernel for gating + expert dispatch
- Memory management: all expert weights loaded, only active ones computed

## Approach

Start with dense models — they're architecturally almost identical to Llama
and mostly need GGUF metadata plumbing. MoE is genuinely new kernel work and
can come after the dense models are running.

For each model, validate against llama.cpp output on the same GGUF file to
verify correctness.

## Success criteria

- Qwen 3.5 4B fine-tune produces correct output
- NeMo 4B fine-tune produces correct output
- At least one MoE model (Qwen 3.6 35B A3B or NeMo 30B A3B) runs correctly
- All existing Llama/TinyLlama tests still pass
